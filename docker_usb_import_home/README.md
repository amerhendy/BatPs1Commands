
# دليل توثيق وتشغيل سكربت استرجاع بيانات وصور المشروع (Home Restore Script)

هذا المستند يقدم شرحاً شاملاً ووظيفياً لسكربت PowerShell المخصص لاسترجاع بيانات ونشر صور المشروع دون الحاجة لاتصال بالإنترنت (Offline Setup).

---

## 1. شرح السكربت ودوره (Overview)

يقوم هذا السكربت بتحويل البيئة المحلية (جهاز البيت) لتطابق التحديثات والداتا التي تم نقلها من جهاز المكتب عبر حزمة نقل (`Office_Transfer_Package`).

### **الوظائف الرئيسية للسكربت:**
1. **التحقق من وجود الحزمة:** يتأكد من وجود مجلد الشحنة وملف قاعدة البيانات المضغوط.
2. **التنظيف الشامل:** يقوم بإيقاف ومسح جميع حاويات (Containers) و مجلدات البيانات (Volumes) القديمة لضمان عدم وجود تضارب.
3. **تحميل صور دوكر (Docker Load):** يقوم باستيراد 7 صور `Docker Tar` محلياً وبدون الحاجة لإنترنت (Offline).
4. **استرجاع قاعدة البيانات:** ينشئ Volume جديد باسم `default_postgres_data` ويستخرج بداخل بيانات PostgreSQL من ملف التراسل.
5. **تعديل إعدادات التكوين:** يستبدل أسماء الصور المحددة داخل ملف `docker-compose.yml` لتشير إلى النسخ المحملة (`office_version`).
6. **تشغيل السيستم:** يطلق كل الخدمات المحددة في `docker-compose.yml` في الخلفية (`-d`).

---

## 2. متطلبات التشغيل (Prerequisites)

| المتطلب | التفاصيل / الوصف |
| :--- | :--- |
| **نظام التشغيل** | Windows 10/11 مع تفعيل ميزة WSL2 أو Hyper-V |
| **الصلاحيات** | **صلاحيات المسؤول (Run as Administrator)** على PowerShell |
| **البرمجيات المطلوبة** | - **Docker Desktop** (شغّال ومفعل)<br>- **PowerShell 5.1** أو **PowerShell 7+** |
| **المجلدات والملفات** | يجب توافر ملف `docker-compose.yml` ومجلد `Office_Transfer_Package` الذي يحتوي على:<br>- `postgres_backup.tar.gz`<br>- ملفات `.tar` للـ 7 صور (`backend`, `frontend`, `celery_worker`, `celery_beat`, `nginx`, `postgres`, `redis`) |

### **مكان التشغيل (Folder Location Requirement):**
- **شرط أساسي:** يجب تشغيل السكربت من **نفس الفولدر الرئيسي للمشروع (Project Root Folder)** الذي يحتوي على ملف `docker-compose.yml` ومجلد `Office_Transfer_Package`. 
- *السبب:* السكربت يعتمد على الأمر `Get-Location` لتحديد المسار الحالي، ومسارات الملفات مصممة بصورة نسبية (`$PROJECT_DIR`).

## 3. الأمان وطريقة التشغيل (Execution & Security Policy)

تفرض أنظمة Windows قيوداً على تشغيل سكربتات PowerShell لحماية الجهاز. لتشغيل السكربت بدون مشاكل صلاحيات أو تغيير آمن للسياسات، اتتبع إحدى الطرق التالية:

### **الطريقة الأولى: التشغيل المؤقت مع تجاوز سياسة الأمان (الموصى بها - آمنة)**
تتيح هذه الطريقة تشغيل السكربت مرة واحدة بتجاوز سياسة المنع دون التغيير الدائم في إعدادات النظام:

1. افتح نافذة **PowerShell** كـ Administrator.
2. انتقل إلى مجلد المشروع:
   ```powershell
   cd "D:\Path\To\Your\Project"
   ```
3. نفذ أمر التشغيل التالي:
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\deploy_home.ps1
   ```

---

### **الطريقة الثانية: السماح بتشغيل السكربتات المحلية بشكل دائم**
إذا كنت تريد تشغيل السكربت بشكل مباشر بالنقر أو باسمه فقط مستقبلاً:

1. افتح PowerShell كـ Administrator ونفّذ الأمر التالي لمنح صلاحيات التشغيل للسكربتات المحلية:
   ```powershell
   Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
   ```
2. لتشغيل السكربت بعد ذلك مباشرة:
   ```powershell
   .\deploy_home.ps1
   ```
