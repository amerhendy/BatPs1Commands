
# 🌲 مجمع الملفات الذكي مع شجرة المشروع (Smart Project Bundler)

أداة رسومية (GUI) مصممة بلغة **PowerShell** تساعد البرمجيين والمطورين على جمع هيكل المشروع (Project Directory Tree) مع المحتوى النصي لملفات برمجية مختارة، ودمجها جميعاً في ملف نصي واحد (`.txt`) بمنتهى السهولة. الأداة مفيدة جداً لمشاركة الأكواد وهيكل المشروع مع النماذج الذكية (AI Models) أو لتسليم المشاريع والمراجعة البرمجية.

## 📝 وصف السكربت ووظيفته

السكربت عبارة عن واجهة واضحة توفر ثلاث خطوات رئيسية لدمج وتوثيق الأكواد:
1. **قراءة شجرة المشروع الكاملة:** يقوم بمسح مجلد المشروع كاملاً ويولّد شجرة رسومية للمجلدات والملفات (تلقائياً يتجاهل المجلدات الضخمة أو الثانوية مثل `node_modules` و `.git`).
2. **اختيار ملفات محددة:** يتيح للمستخدم تحديد مجموعة من الملفات البرمجية لقراءة أكوادها المصدرية وتجميعها.
3. **تصدير ملف مجمع:** يتم دمج شجرة المشروع مع أكواد الملفات المختارة وتصدير الناتج إلى ملف نصي موحد (`.txt`) في نفس مسار السكربت.

---

## ✨ المميزات الرئيسية

* **واجهة مستخدم رسومية (GUI):** تعمل من خلال مكتبات `Windows Forms` دون الحاجة للتعامل مع السطر الأوامر يدوياً.
* **تجاهل الفولدرات الثانوية:** يتخطى المجلدات الزائدة كـ `node_modules` و `.git` لتوفير مساحة وحجم النواتج.
* **إدارة قائمة الملفات:** إمكانية إضافة أكثر من ملف وتصفحها، مع إمكانية حذف أي ملف بسهولة عبر زر `Delete` من لوحة المفاتيح.
* **ترميز UTF-8:** حفظ الناتج بتشفير UTF-8 للحفاظ على اللغة العربية والرموز بشكل صحيح.

## ⚙️ المتطلبات والاشتراطات

لكي يعمل السكربت بشكل صحيح دون أخطاء، تأكد من توافر الآتي:

1. **نظام التشغيل:** نظام Windows (7 / 8 / 10 / 11).
2. **بيئة التشغيل:** 
   * **PowerShell 5.1** أو أحدث (موجود افتراضياً في نظام ويندوز).
   * **.NET Framework** يدعم مكتبات `System.Windows.Forms` و `System.Drawing` (متوفرة تلقائياً على أنظمة ويندوز).
3. **صلاحيات التنفيذ (Execution Policy):** السماح بتشغيل سكربتات PowerShell غير الموقعة رقمياً داخل الجلسة الحالية.
4. **صلاحيات الوصول (Permissions):** صلاحيات قراءة للمجلدات والملفات التي تريد استعراضها، وصلاحية كتابة في المجلد الذي يضم السكربت.

## 📂 مكان التشغيل (Working Directory)

* **هل يجب تشغيل السكربت من نفس الفولدر؟**
  * **نعم، يُفضّل ذلك.** عند إنشاء الملف الناتج يتم حفظه تلقائياً في نفس المجلد الذي يحتوي على ملف السكربت عبر المتغير المدمج `$PSScriptRoot`.
  * إذا قمت بتشغيله من مجلد آخر عبر سطر الأوامر دون حفظ الملف في مسار ثابت، سيتوجب عليك مراعاة مسار حفظ الناتج.

## 🛡️ طريقة التشغيل والأمان

نظرًا لأن أنظمة Windows تمنع تشغيل سكربتات PowerShell افتراضياً لحماية الجهاز، يمكنك تشغيل السكربت بأمان ودون تغيير إعدادات الأمان العامة للجهاز للأبد من خلال خطوة واحدة.

### الخطوة 1: فتح PowerShell
قم بفتح نافذة **PowerShell** أو **Command Prompt (CMD)**.

### الخطوة 2: أمر التشغيل الآمن (Bypass Execution Policy)

استخدم الأمر التالي لتشغيل السكربت بأمان مع التجاوز الموقت لسياسة الحظر **للجلسة الحالية فقط**:

```powershell
powershell -ExecutionPolicy Bypass -File "ProjectBundler.ps1"
```

> 📌 **ملاحظة:** استبدل `ProjectBundler.ps1` بالاسم الفعلي للملف لديك.

### تشغيل السكربت مباشرة من داخل PowerShell:
إذا كنت فتحت PowerShell بالفعل داخل المجلد الموجود به السكربت، يمكنك كتابة:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\ProjectBundler.ps1
```

*الأمر `Set-ExecutionPolicy -Scope Process` يضمن أن التغيير يستمر فقط طوال فترة فتح النافذة الحالية ويرجع لحالته الآمنة بمجرد إغلاقها.*
